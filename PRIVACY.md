# CSBOARD Extension — Privacy Policy

**Last updated:** August 10, 2026
**Effective for:** CSBOARD browser extension version 1.1.0 and later

This document describes the browser extension. The CSBOARD website is governed by its [separate privacy policy](https://csboard.com/en/privacy).

## Summary

- The extension shows prices and exact marketplace lookups locally.
- It includes Steam Market listing tools. A listing is sent directly to Steam only after an explicit user review/confirmation; CSBOARD cannot trigger it.
- Portfolio synchronization is off by default. The one-time code is generated by the user in CSFolder. The user can either pair and opt in from the extension popup, or explicitly click the CSFolder connect action that pairs, enables exactly Inventory + Trade History and triggers the first sync. The extension then schedules automatic sync about once per hour. Failures may delay later automatic attempts.
- Allowed portfolio facts are encrypted inside the extension before transmission to the protected CSBOARD ingestion gateway.
- When Trade History is enabled, accepted-offer correlation facts from the last 30 days may also be uploaded. Active offers and raw Steam offer notes/messages are not uploaded.
- Steam cookies, session/access tokens, passwords and Steam Guard/shared/identity secrets are never uploaded, even encrypted.
- There are no ads, third-party trackers or behavioral analytics in the extension.

## Local page access

Content scripts run only on declared Steam Community, CSFloat and Buff163 URL patterns. They may read the item information necessary for the visible feature: market hash name, asset ID, float, paint seed/index, stickers, tradability/hold state, displayed prices and the current own/trade inventory context. Buff163 enhancements are off by default; when enabled, a strict same-origin endpoint allowlist reads only the marketplace responses required to decorate the current Buff page. Those marketplace-controlled values are labelled `BUFF-reported`, are not presented as independently authenticated CSBOARD facts, remain local, and are neither stored as raw dumps nor uploaded.

The extension also reads the user's CSBOARD settings when “Follow CSBOARD settings” is enabled. CSBOARD authentication uses the site's normal cookie directly with the CSBOARD origin; that cookie is never copied into extension storage or a portfolio payload.

Steam authenticated read credentials are held only in private memory or `chrome.storage.session` by a fixed-operation provider. They are cleared on browser-session end, unpair, account mismatch and authentication failure. No raw Steam credential is returned to a popup/content script, persisted in `chrome.storage.local`, logged or sent to CSBOARD. For recently accepted offers, the provider may inspect the offer note in memory only to derive an allowlisted `buff163` or `csfloat` marketplace hint; it discards the raw note before returning normalized portfolio data.

## Optional portfolio synchronization

When the user pairs a device, enables portfolio uploads and enables one or more sources, manual and automatic sync may transmit these normalized facts:

| Source | Allowed normalized fields |
|---|---|
| Own inventory | Steam account binding, app/context (`2` or `16`), asset/class/instance IDs, market name, amount, tradable/marketable/hold timestamps, float/paint/sticker facts when available, snapshot completeness and observation time |
| Trade history | Up to 100 most recent Steam trades: trade ID and timestamp, counterparty Steam ID, normalized identities of items given and received, and source completeness |
| Accepted-offer correlation | Accepted offers from the last 30 days when Trade History is enabled: offer ID, direction, partner account ID, timestamps, normalized item identities, optional completed trade ID, and an optional allowlisted marketplace hint (`buff163` or `csfloat`) derived locally from the offer note |

The encrypted inventory payload omits redundant localized display `name` and repeated Steam CDN `iconUrl` values. It retains the canonical market name, app/context/asset identity and all ownership, hold, float, paint and sticker facts required for portfolio reconciliation and P2P eligibility.

Accepted-offer correlation is automatic enrichment of the Trade History source, so it has no separate popup switch or counter. Active trade offers and raw Steam offer notes/messages are not uploaded. Version 1.1 also does not upload Steam Market sales/listing history. This does not affect the extension's local trade-offer pages, trade-history view, price overlays or Steam Market tools.

The server uses these facts for the user's portfolio, reconciliation, asset eligibility and user-requested P2P listing registry. A partial snapshot cannot mark an asset sold or missing. Unknown acquisition cost creates a reconciliation item and is not silently treated as zero.

### Data that is always rejected

- Steam or marketplace cookies and cookie jars;
- `sessionid`, `steamLoginSecure`, access/session/bearer tokens or Authorization headers;
- Steam password, Web API key, Steam Guard code, shared secret or identity secret;
- raw authenticated HTML/JSON page dumps, screenshots or storage dumps;
- raw Steam offer notes/messages;
- secret-bearing inspect links;
- arbitrary browsing history or content unrelated to the enabled feature.

A structural secret scanner runs before encryption and again after gateway decrypt. A rejected payload is discarded and only a sanitized error code is retained.

## Chrome Web Store Limited Use

The extension uses user data only to provide or improve its disclosed CS2 trading and portfolio features. User data is not sold, used for personalized advertising, creditworthiness or unrelated profiling, and is transferred only when necessary to provide those features, protect against abuse, comply with law, or as part of a merger, acquisition or sale of developer assets after the user's prior consent. Humans do not read individual user data except with the user's explicit consent for support, when required for security, or when required by law. The extension's use of information complies with the Chrome Web Store User Data Policy, including the Limited Use requirements.

## Encryption and device authentication

HTTPS/TLS is mandatory. Portfolio payloads also use application-layer HPKE (RFC 9180) before `fetch()` so reverse proxies and ordinary access logs receive ciphertext rather than inventory/trade facts. Every request uses a fresh encapsulation and bounded authenticated metadata.

CSFolder is the pairing-consent authority. Its authenticated portfolio page
creates a five-minute, single-use code and stores only a hash. The extension
does not receive a CSFolder session or call CSFolder directly: it includes the
code inside the encrypted CSBOARD pairing request. CSBOARD validates it over a
separate authenticated server-to-server channel and receives only an opaque
binding ID and the linked SteamID64. The dedicated pairing secret is never
present in the extension.

The extension generates a non-extractable per-install P-256 signing key and stores the `CryptoKey` in IndexedDB. CSBOARD receives only the public key. Device signatures, expiry, replay records and idempotency keys bind each request. The gateway's encryption-key set is signed and verified against a public root pinned in the Store build. Missing or invalid keys stop synchronization; payloads are never downgraded to plaintext. `https://csfolder.com` may send only an exact, size-bounded activation message containing protocol version, request ID and the single-use code. It cannot request unpairing, later manual syncs, Steam actions or credentials.

CSBOARD gateway logs are limited to bounded request identifiers, a shortened device hash, key/suite IDs, sizes, result code and latency. They exclude plaintext, ciphertext, HPKE encapsulated keys, device proof, authorization headers and decrypted field values.

## Steam Market actions

`Sell`, `Quick Sell`, `Instant Sell` and bulk sell operate on the user's own Steam inventory. The extension shows the exact asset, Steam wallet currency, seller proceeds, buyer total and fee breakdown. Writes require a trusted user gesture and confirmation and are submitted directly to Steam. Bulk execution is sequential and stops for rate limits, authentication/account mismatch or a price change that requires renewed confirmation.

Neither a CSBOARD webpage nor the protected portfolio gateway can invoke Steam selling, offer creation, acceptance, confirmation or cancellation.

## CSBOARD P2P listing publication

The popup may show server-evaluated eligibility for assets already synchronized
to the user's CSBOARD account. After two separate user actions—requesting an
exact review and confirming it—the extension sends only the operational asset
ID, asset revision, listing ID when unpublishing, USD minor-unit asking price,
terms version and a random idempotency key to the normal cookie-authenticated
CSBOARD listing API. The short-lived intent remains in service-worker memory.

This version can publish or unpublish a listing only. It cannot buy, reserve
funds, create an order, settle money or perform a Steam trade. Those execution
routes are absent from the version 1.1 extension contract. A lost network
response is retried only with the same reviewed intent and idempotency key, so
the extension does not create a second listing to resolve an ambiguous result.

## Storage and control

Local storage contains settings, cached public prices, sanitized batch outcomes, sync cursors and encrypted/outbox metadata. Sensitive Steam read credentials use session-only storage. The device private signing key is non-extractable and stored in IndexedDB.

The popup lets the user disable CSBOARD-settings sync, disable the CSFloat comparison, enable or disable all Buff163 enhancements, disable portfolio uploads or either visible portfolio source, run an immediate manual sync, and unpair. The CSFolder one-click activation always selects only Inventory + Trade History; it cannot silently enable any future source. Accepted-offer correlation follows the Trade History choice and is described before the consent switch; it is not presented as a separate source. Disabling Trade History stops both recent-trade and accepted-offer uploads. Disabling portfolio uploads stops all new manual and automatic uploads. Unpair revokes the server device binding and deletes local queued sync data. Server-side deletion follows the linked CSBOARD account controls and CSBOARD privacy policy.

## Network destinations

- `https://csboard.com` and `https://csboard.trade`: price/rate feeds, optional account settings, encrypted gateway pairing/ingestion, device revoke/status and user-reviewed P2P listing publication.
- `https://csfolder.com`: the user-opened portfolio page generates the one-time pairing code and, only after the user's connect click, may send the exact bounded activation message to the installed extension. The extension has no CSFolder host permission and makes no direct authenticated CSFolder request.
- `https://steamcommunity.com` and `https://api.steampowered.com`: the visible Steam feature, fixed reads and direct user-confirmed Steam actions.
- `https://csfloat.com`: overlays on the marketplace page, public metadata and user-opened search links.
- `https://buff.163.com` and its HTTPS subdomains: opt-in, local-only marketplace display enhancements and user-opened links. No Buff response is sent to CSBOARD.

No other origin may send messages to the extension. CSBOARD origins can request only extension version/capability status. The CSFolder origin can request only the single-use pairing + fixed-source activation described above. Neither surface exposes login state, inventory data, settings, Steam-session status or any Steam write.

## Permissions

| Permission | Purpose |
|---|---|
| `storage`, `unlimitedStorage` | Local public price cache, settings, bounded outbox/status and session-only credential state |
| `alarms` | Manifest V3-safe price refresh, automatic portfolio sync about once per hour after explicit opt-in, and bounded retry scheduling |
| Declared host permissions | Run only the documented Steam/CSFloat/opt-in Buff163 features and communicate with the two CSBOARD production origins |

## No remote executable code

All JavaScript and cryptographic code is bundled with the Manifest V3 artifact. The extension does not execute remotely hosted JavaScript/WASM, `eval`, `new Function` or remote dynamic imports. Network responses are treated as validated data.

## Changes and contact

Material data-use changes require an updated policy, Store disclosure and extension release. Questions or deletion requests may be submitted through <https://github.com/kizilovv/csboard-extension/issues> or the contact information at <https://csboard.com>.
